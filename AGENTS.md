## Project Overview

**higimo.ru** – личное портфолио, резюме менеджера по продуктам, отслеживание поездок, инструменты менеджмента фотографий ВКонтакте, магазин и различные утилиты.

- **Фреймворк**: `preact@10` (с "preact/compat" для совместимости с React)
- **Маршрутизация**: `preact-iso` (отложенная загрузка, динамические маршруты)
- **Состояние**: `@preact/signals` + перехватчики реакции (`useState`, `useEffect`, `useReducer` и т.д.)
- **Инструмент сборки**: Vite (с `@preact/preset-vite`)
- **Язык**: TypeScript (частично включен строгий режим)
- **HTTP-клиент**: клиентская оболочка `sendRequest` поверх `XMLHttpRequest`
- **Тестирование**: Vitest + JSDOM + `@testing-library/preact`
- **Стилизация**: обычные CSS-файлы (без CSS-in-JS)

## Ключевые архитектурные шаблоны

### 1. Маршрутизация с `preact-iso`

Маршруты определяются в `src/index.tsx` с помощью `<Router>` и `<Route>`.  
Динамические маршруты (например, `/:vendor/:project/`) используют словарь `ROUTE_LINKS` с помощью помощника `generateLink`, для того, чтобы использовать автодополнение на основе типов.

- **Отложенная загрузка**: `lazy(() => import(...))` для больших страниц (например, PortfolioSandbox, ResumeProductPage).
- **Закрытые маршруты**: оболочка `<PrivateRoute>` проверяет `useAuth()` и перенаправляет на вход с помощью `backpath`.

### 2. Взаимодействие с API

- `useApi<T>(url, значения)` – пользовательский хук, который обрабатывает состояния загрузки/ошибки, отправляет запрос через `sendRequest`.
- `sendRequest` – необработанная оболочка XHR с классом `ApiError`.
- Базовый URL API: `/api/v2/` (проксируется к серверной части).
- Особый случай: если URL заканчивается на "-1", "useApi" возвращает пустой объект (пропускает запрос).

### 3. Идентификация

- Функция `useAuth()` (основанная на сигнале) проверяет `/api/v2/auth/me` один раз.
- Сохраняет состояние авторизации в "authSignal" (предотвращает многократные запросы).
- "PrivateRoute" использует его для защиты страниц, доступных только администраторам.
- Отдельная аутентификация ВКОНТАКТЕ (`VkContext`).

### 4. Управление состоянием

- **Сигналы** (`@preact/signals`) – используются только для авторизации и торговых продуктов (глобальный синглтон).
- **Контекст реакции** – для авторизации ВКОНТАКТЕ и глобального флага "не найден".
- **Состояние локального компонента** – `useState`, `useReducer`, пользовательские хуки (`useSmartTags`, `useTableProject` и т.д.).

### 5. Формы и проверка

- `react-hook-form` + пользовательский компонент `showError`.
- Помощники `FormButton`, `ShowFormResult`.
- Упоминания о вводе (`react-autocomplete-input`), используемые в Nokia meetings.

### 6. Стратегии фильтрации тегов

Несколько перехватчиков/утилит фильтрации в `utils/filter-tag-strategy/`:

- `filterTagAnyStrategy` – ИЛИ по всем выбранным тегам.
- `Filtertagandgroupstrategy` – И между группами, ИЛИ внутри каждой группы.
- `Фильтрация групповой стратегии` – ИЛИ между группами, ИЛИ внутри групп.

Используется в туристических барах, портфолио проектах, галерее аккордов и т.д.

## Именование каталогов

Каталог `src/components` для всех переиспользуемых частей интерфейса. Не является страницей. Группируется по функциональным доменам, а не по типу.

Важно отдельно группировать в:

* ui — примитивы без бизнес-логики: кнопки, теги, тайлы, хлебные крошки, контейнеры, логотип и т. д.;
* form — формы и их части;
* util — вспомогательные компоненты-обёртки, где нет визуальной части.

Каталог `src/page` только для страниц. Каждый компонент повторяет логическую структуру страниц сайта.

### Правила именования компонентов

Для файлов используется kebab-case. Каждый компонент (`page` и `components`) обязательно размещаются в отдельной директории по названию компонента, сам помпонент располагается в `index.tsx`. В директории может находиться `index.test.tsx`, вспомогательные типы `my-component/types.ts` и стили `style.css`. Например, `favorite-page/index.tsx`, `start-contract/index.tsx`. В коде компонент называется в CamelCase.

Для объявления компонента всегда используется стрелочная функция и сразу экспорт без default

URL-параметры (:idcode, :vendor) передаются через useRoute() внутри компонента страницы.

## Рабочий процесс участников / агентов

При работе с этой кодовой базой:

1. **Разберитесь с маршрутизацией** – все маршруты указаны в `src/index.tsx` и `dic/ROUTE_LINKS.ts`
1. **Разберитесь с основными типами API** – все типы в директории `src/api-types/*`
3. **Используйте `useApi` для выборки данных** – не вызывай `sendRequest` в компонентах без острой необходимости.
2. **Переиспользуй существующие компоненты** из `components/ui/`
6. **Всплывающие уведомления** – используй `toast.success("сообщение")` из `toast`, везде где нужно сообщить о результате
7. **TypeScript** – избегай `any`; используйте помощники `utils.type.ts` (`Brand`, `valueOf`, `ISOString`).
7. **Тестирование** – обязательно пиши тесты для новых утилит, стратегий фильтрации, сложных хуков и критических компонентов (PrivateRoute, ApiBoundary).
9. **Стилизация** – добавь классы CSS в соответствующий `style.css`; избегай inline-стилей
9. **Сервисы** – для POST/PUT/PATCH запросов создавай класс-сервис в `src/services/`. Используй вспомогательные функции `compact` и `omit` для чистки тела запроса.
10. **Комментарии** – не пиши очевидные комментарии. Если логика сложная – добавь пояснение на русском.

### Поддержание консистентности

- **Никогда не хардкодь URL** в компонентах – только через `API_ROUTE`.
- **Не используй `as any`** для обхода типов – исправляй типы или расширяй интерфейсы.
- **Для всех параметризованных путей** используй `generateLink` – это даст автодополнение и проверку типов.
