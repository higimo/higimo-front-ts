Одна важная ловушка с isSubmitSuccessful
isSubmitSuccessful в RHF означает «обработчик submit разрешился без throw», а не «API ответил 200». Ваш handleSubmit сейчас ловит ошибку и не пробрасывает её — значит, даже при ошибке API isSubmitSuccessful станет true, и хук удалит драфт. Это не то, что вы хотите.

Хук не может отличить «реальный успех» от «пойманной ошибки» — сигнала нет. Два выхода:

throw error в конце catch — одна строка, семантически честно: «submit провалился». Тогда isSubmitSuccessful = false, драфт сохраняется. Это не «логика в потребителе про драфты» — это корректный контракт с RHF, который полезен и без персиста (например, если позже захотите блокировать кнопку по isSubmitSuccessful).

tsx
} catch (error) {
    toast.error(...)
    throw error
}
Оставить как есть — тогда при ошибке API драфт будет удалён, и пользователь потеряет введённое. Не рекомендую.

Если категорически не хотите менять handleSubmit — скажите, добавлю в хук clearDraft для явного вызова (но это уже логика в потребителе, от которой вы уходили).
